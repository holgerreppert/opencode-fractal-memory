# Changelog

## v0.7.18
- **Compaction RSS/capture runaway fix** (`src/plugin/hooks/compaction.ts`): opencode compaction ballooned RSS to 9+ GB and took minutes because middle-term snapshots recursively re-captured prior snapshots — each `middle-term:` node embedded the full content of older `middle-term:` nodes (verified: one 195 MB node embedding 38.6 + 41 + 41 + 18.2 MB predecessors → exponential growth; DB was 354.5 MB across 1073 nodes). Root causes and fixes:
  - **Recursive snapshot growth**: the fallback fill (cache empty → `listNodes("project")` → 8 most recent) included prior `middle-term:`/`storedcontext:` nodes with full content, then `captureContent` JSON-stringified the entire working cache uncapped into a new middle-term node. Fixed: fallback now **excludes snapshot labels** (`middle-term:`/`storedcontext:`), and capture is capped at **12 KB total / 2 KB per entry** (`MAX_CAPTURE_CHARS`, `MAX_CAPTURE_ENTRY_CHARS`).
  - **RSS from unbounded message fetch**: `client.session.messages({limit: 50})` pulled 50 full messages and appended `part.text` **uncapped** (only reasoning/tool/result parts were sliced). Fixed: `limit` 50 → **20**, `part.text` sliced to **2 KB** per message (`MAX_MESSAGE_TEXT_CHARS`).
  - **ONNX embedding in the hook**: `generateEmbeddingWithSegments` ran the embedding model in-process during compaction. Fixed: storedcontext nodes are now created with `embedding: null` (semantic recall of raw session dumps is marginal — `computeQualityMultiplier` already demotes `storedcontext` ×0.5); embedding stays available on the middle-term + storedcontext capture path only for nodes created through the normal `memory(mode="set")` flow.
- **Working-cache content cap** (`src/application/cache.ts`): `addToWorkingCache` now truncates entry content to **8 KB** (`MAX_CACHE_CONTENT_CHARS`) — tool outputs from `memory_get`/`drilldown`/`search`/`fetch` can no longer inject multi-MB strings into the compaction capture path. CACHE_MAX_SIZE (8) / TTL (2h) unchanged.
- **Giant-node cleanup script** (`scripts/cleanup-giant-nodes.ts`): one-off `bun run scripts/cleanup-giant-nodes.ts --dry-run` (preview) / `--force` (delete) for project nodes whose `length(content) > 1 MB`. Ran against the live DB: **10 nodes / 345.4 MB freed** (all recursive `middle-term:` captures of session `ses_170ca2df5ffeXEfIT0oZld4KJc`), DB content 354.5 MB → 9.1 MB.
- Tests: 5 new — `src/application/cache.test.ts` (3: 8 KB truncation, small content intact, 8-entry cap) + `src/plugin/hooks/compaction.test.ts` (2: snapshot-label exclusion from fallback, 2 KB/entry + 12 KB total capture caps, driven through the real `compacting` hook with a mock store). typecheck + lint clean. Requires opencode restart; **the next compaction will now produce ~12 KB middle-term snapshots and bounded RSS**.

## v0.7.16
- **Auto-retrieve un-quieted (A+D)**: fixes the regression where `messages_transform` injection went silent after 2026-08-02. Root cause: the Round-1 stale-summary fix (v0.7.11-era, commit 66d6195) added a multiplicative recency penalty `(0.3 + 0.7×recencyScore)` to `importance` in `computeRRFScores` (src/storage/queries/search-helpers.ts) + wired `autoInjection.minScore` into all phases. With a 24h recency half-life, ANY node older than ~2 days scored below the 0.5 gate → ALL durable-knowledge injection suppressed (stale summary: created 2026-07-26, last injected 124×, then nothing at all since Aug 2 12:40). Two-part fix:
  - **A — importance is pure relevance**: removed the multiplicative recency penalty from `computeRRFScores`. `importance = normalized RRF [0,1] × qualityMultiplier`; recency (`computeRecencyScore`) now only breaks ties in the sort (equal relevance → fresh first, level ≥ 1 anchors from createdAt). Old-but-relevant nodes can pass the gate again.
  - **D — per-session dedup replaces time-decay as the anti-flood mechanism**: `createMessagesTransformHandler` (src/plugin/hooks/messages-transform.ts) keeps `injectedPerSession: Map<sessionId, Set<nodeId>>` (capped 32 sessions) — a node injected once in a session is never re-injected that session. The real original bug was REPETITION (same node every turn), not staleness; dedup targets that directly.
- Tests: 3 new/rewritten RRF recency tests (single-candidate normalization is age-independent; genuine-tie ordering via swapped semantic/BM25 ranks; createdAt anchoring for level ≥ 1) + 2 dedup tests (same-session blocked, new-session allowed; mock nodes now carry `id`). 475 non-benchmark tests pass, lint + tsc clean. Requires opencode restart.

## v0.7.10
- **Tiered command compression** (`src/application/command-compression.ts`, strategies in `src/application/command-compression/`): Replaces the flat "compress everything large" model with graduated tiers:
  - **Tier 0 — verbatim pass-through**: Outputs under `verbatimBelowLines` (default 40) or < 80 chars are never compressed. Small `ls`/`grep`/`git status` results arrive intact.
  - **Net-win gate**: Compression is skipped unless BPE-estimated token savings clear `netWinMinTokens` (default 24) — no net-loss invocations.
  - **Benign-aware threshold**: Clean output compresses only beyond `benignThreshold` (1000 lines); error-bearing output beyond `errorThreshold` (500). Error output always passes through verbatim (`isSignalOutput`).
  - **grep** (`strategies/grep.ts`): Matched lines kept verbatim up to `keepMatches` (15); beyond that, first 15 matched lines + per-file counts + "… +N more". Strict `path:line:content` detection rejects ps/table-style lines (fixes the "no-ext: 1 file, 5 77916996 1229920 pts/0 Sl+" garble).
  - **ls** (`strategies/ls.ts`): Filenames kept verbatim up to `keepNames` (50); never folded to bare "N files". `tree` shares this path.
  - **git status** (`strategies/git.ts`): Changed-file list is the payload and is always kept (up to 50 files + "… +N more"); only headers/instructions are stripped. Fixes a pre-existing trim bug that silently dropped the file list.
  - **tables** (`shape.ts`): Header + rows kept verbatim up to `keepRows` (20); token-count-based table detection replaces the 2+space heuristic that misread `ps aux` as 1 column. Optional per-command `essentialColumns` column trimming.
  - **Always-reversible** (`src/plugin/hooks/compression.ts`): Original output stashed on *every* compression (was > 2000 chars only) with `[Original stashed — cat <path>]` recovery marker. New `[ids_preserved: …]` factsheet lists SHAs/UUIDs/versions dropped by lossy summaries.
  - **Path-safe abbreviations** (`utils.ts`): `applyWordAbbreviations` never rewrites tokens containing `/`, `.`, or `:` — fixes the `src/management/…` → `src/mgmt/…` path corruption.
- **Config**: New `commandCompression` knobs — `netWinMinTokens`, `verbatimBelowLines`, `benignThreshold`, `errorThreshold`, `keepMatches`, `keepNames`, `keepRows`, `essentialColumns` (all with defaults, overridable in `opencode-mem.json`).
- Tests: 88 pass (was 79); lint 0 errors; build clean.
